# gptaku 플러그인 검증 프로토콜 (Verification Policy)

> 근거: cursor/plugins `cursor-team-kit/verify-this` 스킬 분석(2026-08-31) — 우리 "주장 전 실측" 원칙을
> 재현 가능한 프로토콜로 구체화한 것. 게이트/판정을 내장하는 플러그인(goaljaby·insane-review·
> insane-research·kkirikkiri 등)이 다음 정규 릴리즈에서 이 SSOT를 참조한다.

---

## 0. 한 줄 원칙

**검증은 요약이 아니다** — 특정 주장을 반복 가능한 증거로 입증하거나 반증하는 행위다.

## 1. 프로토콜 (5단계)

1. **반증 가능한 형태로 재진술** — 조건 + 지표 + 임계값. "코드가 더 깨끗해졌다"류 비측정 주장은 검증 대상이 아니다 → 측정 가능한 주장으로 바꿔 달라고 요구한다.
2. **최소 반증 표면 선택** — 그 주장을 깰 수 있는 가장 작은 로컬 실험을 고른다.
3. **baseline 캡처** — 변경 전 상태(머지 베이스, 이전 커밋, 실패 재현)에서 측정.
4. **treatment 캡처** — 변경 후 상태에서 **같은 명령·같은 데이터·같은 환경**으로 측정.
5. **원자료 대조** — 숫자, 터미널 출력, 스크린샷, HTTP 응답 등 원자료끼리 비교. 기억이나 요약으로 비교하지 않는다.

## 2. 판정은 셋 중 하나만

| 판정 | 조건 |
|---|---|
| `VERIFIED` | baseline과 treatment가 예측 방향으로, 주장한 임계값만큼, 명백한 교란 없이 다름 |
| `NOT VERIFIED` | 차이가 없거나 반대 방향 |
| `INCONCLUSIVE` | 측정 실패·교란 존재·재현 불가 — **이유를 명시**하고 다음 실험을 제안 |

중간 표현("대체로 됨", "거의 확실") 금지. 확신이 안 서면 `INCONCLUSIVE`다.

## 3. 산출물 배치 (선택)

증거를 남길 가치가 있으면:

```
/tmp/verify/<claim-slug>/
├── claim.md        # 반증 가능한 형태의 주장
├── baseline/       # 변경 전 원자료
├── treatment/      # 변경 후 원자료
└── verdict.md      # 판정 + 근거
```

민감한 코드·프롬프트·응답이 섞이면 디스크 저장 대신 최소 인라인 증거만 유지한다.
